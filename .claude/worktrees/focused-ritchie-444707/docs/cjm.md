# Eidos SCV — Customer Journey Map

Карты пользовательского пути для двух ключевых ролей платформы единого профиля
клиента (Single Customer View). Описывают, как пользователь достигает своих целей,
работая с системой.

---

## Роль 1. Администратор источников данных

**Кто это:** специалист, который подключает к платформе новые системы-источники
и поддерживает их работу.

**Главная ценность:** подключение нового источника данных **без программирования** —
силами одного человека через интерфейс.

### A1. Оценка нового источника

| | |
|---|---|
| Цель | Понять, какие данные о клиенте источник может передать |
| Действия | Сверяет поля источника с эталонным профилем клиента платформы |
| Точка контакта | Справочник полей единого профиля |
| Ценность для пользователя | Сразу видит «целевую картину»: какие поля обязательны и в каком виде их ждёт платформа |

### A2. Регистрация источника

| | |
|---|---|
| Цель | Завести новый источник в системе и выдать ему доступ |
| Действия | Создаёт карточку источника: название, код, уровень доверия; получает ключ доступа |
| Точка контакта | Реестр источников → форма создания |
| Ценность для пользователя | Единый список всех подключённых систем в одном месте, доступ выдаётся в пару кликов |

### A3. Настройка соответствия данных

| | |
|---|---|
| Цель | Сопоставить поля источника с полями единого профиля клиента |
| Действия | Связывает каждое поле источника с полем профиля, задаёт правила преобразования и проверки данных |
| Точка контакта | Конструктор контракта данных |
| Ценность для пользователя | Гибкая настройка под любой формат источника без участия разработчиков |

### A4. Запуск приёма данных

| | |
|---|---|
| Цель | Включить поток данных от источника в платформу |
| Действия | Активирует канал получения данных и передаёт источнику ключ доступа |
| Точка контакта | Настройки приёма данных |
| Ценность для пользователя | Управление потоками данных из интерфейса, без обращения в техподдержку |

### A5. Проверка перед запуском

| | |
|---|---|
| Цель | Убедиться, что данные источника корректно доходят до профиля клиента |
| Действия | Отправляет пробные данные и наблюдает, сколько записей принято, а сколько отклонено |
| Точка контакта | Дашборд → активность источников |
| Ценность для пользователя | Уверенность в качестве интеграции ещё до боевого запуска |

### A6. Сопровождение источника

| | |
|---|---|
| Цель | Поддерживать источник в актуальном состоянии |
| Действия | Корректирует правила сопоставления, меняет уровень доверия, при необходимости отключает источник |
| Точка контакта | Реестр источников, конструктор контракта |
| Ценность для пользователя | Полный контроль над источником в течение всего жизненного цикла |

---

## Роль 2. Дата-стюард (специалист по качеству данных)

**Кто это:** специалист, отвечающий за достоверность единого профиля клиента.

**Главная ценность:** прозрачность и доверие к данным — каждое спорное расхождение
разрешается человеком осознанно, а происхождение любого факта о клиенте можно
проследить.

### S1. Обзор спорных записей

| | |
|---|---|
| Цель | Оценить объём и приоритет накопившихся расхождений |
| Действия | Просматривает сводку: сколько записей ждут решения и какого они типа |
| Точка контакта | Дашборд дата-стюарда |
| Ценность для пользователя | Понятная картина нагрузки и приоритетов с первого экрана |

### S2. Разбор расхождения

| | |
|---|---|
| Цель | Понять суть конфликта между источниками |
| Действия | Открывает спорную запись и сравнивает значения от разных источников поле за полем |
| Точка контакта | Экран разбора конфликта |
| Ценность для пользователя | Расхождения подсвечены — суть конфликта видна за секунды |

### S3. Разрешение конфликта

| | |
|---|---|
| Цель | Зафиксировать достоверное значение в профиле клиента |
| Действия | Выбирает, какому источнику верить, либо собирает корректную запись вручную |
| Точка контакта | Экран разбора конфликта → действия |
| Ценность для пользователя | Контроль над качеством профиля остаётся за человеком, а не за алгоритмом вслепую |

### S4. Запись из неизвестного источника

| | |
|---|---|
| Цель | Решить судьбу данных от ещё не подтверждённого источника |
| Действия | Создаёт профиль клиента вручную либо отклоняет запись |
| Точка контакта | Очередь спорных записей |
| Ценность для пользователя | Ни одна сомнительная запись не попадает в профиль без проверки |

### S5. Поиск и проверка профиля

| | |
|---|---|
| Цель | Найти клиента и проверить достоверность его данных |
| Действия | Ищет клиента по ключевым реквизитам и открывает его карточку |
| Точка контакта | Поиск → карточка клиента |
| Ценность для пользователя | Полный профиль клиента в одном окне |

### S6. Происхождение и история данных

| | |
|---|---|
| Цель | Понять, откуда взялось каждое поле и как оно менялось |
| Действия | Смотрит источник и дату каждого значения, открывает историю изменений |
| Точка контакта | Карточка клиента → происхождение и история |
| Ценность для пользователя | Полная прослеживаемость данных — доверие и готовность к аудиту |

---

## Итог: ценность платформы по ролям

**Администратор** превращает подключение источника из ИТ-проекта в самостоятельную
настройку через интерфейс: новые системы добавляются быстро, без разработки и под
полным контролем.

**Дата-стюард** получает инструмент управления качеством данных: спорные записи
разрешаются осознанно, а каждый факт о клиенте прозрачен и прослеживаем — это основа
доверия к единому профилю клиента.
