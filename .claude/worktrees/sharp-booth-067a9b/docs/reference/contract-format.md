# Формат дата-контракта

Контракт хранится в реестре (`eidos_registry`) и редактируется через
[API eidos-stage](api/stage.md#дата-контракт) или конструктор контракта.
Практическое руководство — [Дата-контракт](../sources/data-contract.md).

## Контракт

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | целое | Идентификатор контракта |
| `sourceId`, `sourceCode` | целое, строка | Источник |
| `entityType` | `PERSON` или `LEGAL_ENTITY` | Тип сущности; передаётся параметром `entityType` в путях API |
| `clientIdentifierField` | строка | Путь к идентификатору клиента в данных источника |
| `version` | целое | Счётчик изменений; растёт при любом изменении контракта и его правил |
| `fields` | массив | Правила полей |

Контракт уникален для пары «источник + тип сущности».

## Правило поля

| Атрибут | Тип | Обязателен | Описание |
|---|---|---|---|
| `id` | целое | — | Идентификатор правила; присваивается при создании |
| `sourceFieldName` | строка | да | Путь в данных источника: ключи через точку, от объекта `data` |
| `targetGrField` | строка | да | Поле Золотой записи в форме контракта (`GR_…`); должно существовать в каталоге полей типа сущности |
| `dataType` | перечисление | да | Тип правила — см. ниже |
| `required` | логическое | нет | Отклонять карточку без значения; по умолчанию `false` |
| `sourceDateFormat` | строка | нет | Шаблон даты Java `DateTimeFormatter`; для `DATE`. Без шаблона — `yyyy-MM-dd` |
| `validationRegex` | строка | нет | Регулярное выражение Java; значение должно совпасть целиком |
| `defaultValue` | строка | нет | Значение, если источник не прислал своё; не перекодируется и не разбирается |
| `ordering` | целое | нет | Порядок отображения; по умолчанию 0 |
| `valueMap` | объект строка → строка | нет | Таблица значений: перекодировка и список допустимых значений |

## Типы правил

| `dataType` | Проверка на шлюзе | Преобразование в `eidos-stage` |
|---|---|---|
| `STRING` | — | Значение строкой |
| `DATE` | Разбор по `sourceDateFormat` | В `yyyy-MM-dd` |
| `INTEGER` | Целое 32-битное (`Integer.parseInt`, пробелы по краям допускаются) | Строкой; приведение к типу поля записи |
| `BOOLEAN` | `true` или `false`, без учёта регистра | Строкой; приведение к логическому |
| `GENDER` | Нет, кроме таблицы значений | Через таблицу значений; результат должен быть `M` или `F` |
| `ARRAY` | Значение — массив | Массив целиком |
| `STRUCT` | Значение — массив | Массив объектов целиком; лишние ключи элементов отбрасываются |

## Соответствие типов

| Логический тип поля записи (каталог) | Тип правила |
|---|---|
| `STRING` | `STRING` |
| `DATE` | `DATE` |
| `GENDER` | `GENDER` |
| `BOOLEAN` | `BOOLEAN` |
| `INTEGER` | `INTEGER` |
| `DECIMAL` | `STRING` |
| `STRING_ARRAY` | `ARRAY` |
| `STRUCT_ARRAY` | `STRUCT` |

## Порядок обработки поля

На шлюзе:

1. Значение читается по пути. Для `ARRAY` и `STRUCT` проверяется
   обязательность и что значение — массив; дальше шаги не выполняются.
2. Пустое значение: если правило обязательное и `defaultValue` не задан —
   нарушение `missing required field`. Иначе проверка поля завершена.
3. Если `valueMap` не пуст, значение должно быть его ключом.
4. Если задан `validationRegex`, значение должно ему соответствовать.
5. Проверка типа: `DATE`, `INTEGER`, `BOOLEAN`.

В `eidos-stage`:

1. `ARRAY`, `STRUCT` — поддерево переносится как есть.
2. Пустое значение — подставляется `defaultValue` (или поле остаётся пустым).
3. Значение заменяется по `valueMap`, если в таблице есть такой ключ.
4. `DATE` приводится к `yyyy-MM-dd`.
5. Запись проверяется по ограничениям Золотой записи.

Идентификатор клиента читается по `clientIdentifierField` строкой.

## Пример

```json
{
  "clientIdentifierField": "client_id",
  "fields": [
    {"sourceFieldName": "phone", "targetGrField": "GR_mobilePhoneMain", "dataType": "STRING", "required": true, "validationRegex": "^998\\d{9}$"},
    {"sourceFieldName": "person.birth_date", "targetGrField": "GR_BirthDate", "dataType": "DATE", "required": true, "sourceDateFormat": "dd.MM.yyyy"},
    {"sourceFieldName": "person.gender", "targetGrField": "GR_Gender", "dataType": "GENDER", "required": true, "valueMap": {"1": "M", "2": "F"}},
    {"sourceFieldName": "citizenship_code", "targetGrField": "GR_CitizenshipId", "dataType": "STRING", "required": true, "defaultValue": "860"}
  ]
}
```
