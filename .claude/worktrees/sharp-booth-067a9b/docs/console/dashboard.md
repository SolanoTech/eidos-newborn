# Дашборд и качество данных

## Дашборд

**Консоль администратора → Дашборд** — сводка состояния платформы.

### Плитки

| Плитка | Значение |
|---|---|
| Golden Records | Число Золотых записей физлиц; ниже — сколько карточек принято за текущие сутки |
| Источников | Число источников в реестре: сколько отмечено активными и сколько выключено |
| Конфликтов | Записей в очереди разбора физлиц; ниже — сколько из них конфликты при равном доверии |
| Auto-merge rate | Доля записей без конфликтов: `1 − конфликты / Golden Records`, в процентах |

### Активность источников

Таблица по каждому источнику реестра: сколько карточек принято и отклонено
**за текущие сутки** (с полуночи по часам сервера) и статус источника. Что
считается принятым и отклонённым — [Статистика приёма](../concepts/ingestion.md#статистика-приёма).

- Рост «Отклонено» у источника — повод посмотреть ответы шлюза или журнал
  `eidos-gateway`.
- Для источников, передающих данные через Kafka, одно ошибочное сообщение даёт
  несколько отклонений: шлюз повторяет его несколько раз.

### Качество Golden Records

| Показатель | Как считается |
|---|---|
| Валидность телефона | Доля записей, где телефон соответствует `^998\d{9}$` |
| Валидность ПИНФЛ | Доля записей с ПИНФЛ из 14 цифр |
| Полнота отчества | Доля записей с заполненным отчеством |
| Свежесть | Доля записей, изменённых за последние 30 дней |

Показатели считаются по всем записям физлиц в момент открытия страницы. Для
юрлиц показателей пока нет.

Кнопка **Отчёт за сутки** в текущей версии отчёт не формирует.

## Качество данных

**Консоль администратора → Качество данных** повторяет четыре показателя
качества. Блок «Открытые инциденты» — демонстрационный: его содержимое не
связано с данными платформы.

## Как пользоваться

- **Ежедневно** смотрите на отклонения по источникам и размер очереди
  конфликтов.
- **После подключения источника** сравните «Принято» с тем, что источник
  отправил.
- **Валидность ниже 100 %** означает, что в базе есть записи с телефоном или
  ПИНФЛ в неверном формате. Через приём такие значения не проходят: формат
  проверяется при каждой карточке. Значит, записи попали в базу в обход приёма —
  например, загружены напрямую SQL-скриптом.
