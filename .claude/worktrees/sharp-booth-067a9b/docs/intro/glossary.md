# Глоссарий

Архив записи
:   Копии состояния Золотой записи после каждого изменения. Каждая копия
    хранит номер версии, на которую запись перешла. Хранится в таблицах
    `golden_record_archive` и `legal_entity_archive`.

Внешний идентификатор (external id, `client_source_identificator`)
:   Идентификатор клиента или мерчанта в системе-источнике. Хранится в связке с
    Золотой записью и источником; по нему платформа узнаёт клиента при
    следующей передаче данных.

Дата-контракт
:   Правила, по которым данные конкретного источника превращаются в Золотую
    запись: путь к полю, целевое поле, тип, формат, допустимые значения.
    Задаётся на пару «источник + тип сущности». См.
    [Дата-контракт](../sources/data-contract.md).

Дата-стюард
:   Специалист по качеству данных: разбирает конфликты и проверяет профили
    клиентов.

Золотая запись (golden record)
:   Единая запись о клиенте, собранная из данных всех источников. Для физлица
    идентификатор имеет вид `GR_<uuid>`, для юрлица — `LE_<uuid>`.

ИНН
:   Идентификационный номер налогоплательщика — девять цифр. Ключ
    сопоставления юридических лиц.

Источник (система-источник)
:   Внешняя система, которая передаёт данные о клиентах в платформу. В реестре
    у источника есть код, название, токен доступа и уровень доверия.

Код источника
:   Уникальный короткий идентификатор источника в реестре, например `bank-1`.
    Подставляется платформой во все данные, пришедшие с токеном источника.

КЕК (KEK, key encryption key)
:   Ключ шифрования ключей. Хранится в OpenBao и не покидает его: сервис
    передаёт хранилищу ключ данных и получает его в зашифрованном виде.

Ключ данных (DEK, data encryption key)
:   Ключ, которым шифруются сами значения. Хранится только в виде,
    зашифрованном KEK.

Мерчант
:   Юридическое лицо — клиент или партнёр (например, торговая точка). В
    платформе — синоним юрлица.

Незавершённая запись (tentative)
:   Данные, которые не удалось привязать к Золотой записи автоматически: от
    незарегистрированного источника или с конфликтом при равном доверии.
    Ждут решения в очереди разбора.

ПИНФЛ
:   Персональный идентификационный номер физического лица — 14 цифр. Основной
    ключ сопоставления физических лиц.

Происхождение поля (provenance)
:   Сведения о том, какой источник дал текущее значение поля Золотой записи и
    когда это произошло.

Серая зона (grey zone)
:   Ситуация, когда источник с тем же уровнем доверия, что у владельца поля,
    присылает другое значение. Запись не меняется, входящие данные уходят в
    очередь ручного разбора. См. [Незавершённые записи и конфликты](../concepts/conflicts.md).

Слепой индекс (blind index)
:   HMAC от комбинации полей. Позволяет искать записи на точное равенство, не
    сравнивая сами значения, в том числе после того, как значения будут
    заменены токенами. См. [Защита персональных данных](../concepts/data-protection.md).

Слияние (merge, survivorship)
:   Обновление существующей Золотой записи данными из нового источника по
    правилам доверия. См. [Слияние и происхождение](../concepts/merge.md).

Согласие
:   Разрешение клиента на определённый вид обработки данных с датами начала и
    окончания действия. См. [Согласия](../concepts/consents.md).

Сопоставление (matching)
:   Поиск существующей Золотой записи для входящей карточки. См.
    [Сопоставление](../concepts/matching.md).

Сырьё (raw data)
:   Данные источника в том виде, в каком они пришли, до преобразования.
    Хранятся в MongoDB.

Тип сущности
:   Вертикаль, к которой относятся данные: физическое лицо (`PERSON`) или
    юридическое лицо (`LEGAL_ENTITY`). Определяется каналом приёма.

Токен источника
:   Секрет, по которому платформа узнаёт источник. Передаётся в заголовке
    `X-Access-Token` HTTP-запроса или Kafka-сообщения.

Уровень доверия (trust level)
:   Целое число, задающее приоритет источника при слиянии: значение источника
    с более высоким уровнем заменяет значение источника с более низким.
