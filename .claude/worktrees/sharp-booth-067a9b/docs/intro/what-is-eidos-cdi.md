# Что такое Eidos CDI

## Задача

Сведения об одном и том же клиенте обычно живут в нескольких системах: в
автоматизированной банковской системе, в процессинге, в CRM, в партнёрских
сервисах. Каждая хранит свою версию: где-то другой телефон, где-то устаревший
паспорт, где-то фамилия с опечаткой. Ответить на простой вопрос «что мы знаем об
этом клиенте и насколько этому можно верить» оказывается трудно.

**Eidos CDI** (Customer Data Integration) решает эту задачу: принимает данные из
систем-источников, приводит их к единому виду и сводит в одну запись о клиенте —
**Золотую запись** (golden record). Для каждого поля Золотой записи известно, из
какого источника пришло значение и когда.

## Место в платформе Eidos

Eidos — клиентская платформа данных (CDP). CDI — её интеграционный слой и
основа для остальных модулей: сегментация, маркетинговые кампании и аналитика
работают уже с Золотыми записями, которые сформировал CDI. Эта документация
описывает только модуль CDI.

В материалах проекта встречается несколько близких терминов:

| Термин | Что означает в Eidos |
|---|---|
| **CDP** (Customer Data Platform) | Платформа целиком |
| **CDI** (Customer Data Integration) | Модуль интеграции и консолидации данных — предмет этой документации |
| **MDM** (Master Data Management) | Дисциплина управления эталонными данными; CDI реализует её для клиентов |
| **SCV** (Single Customer View) | Результат работы CDI — единый профиль клиента |

## Что делает модуль

- **Принимает данные** от систем-источников синхронно по REST или потоком из
  Kafka. Каждый источник предъявляет свой токен — платформа сама определяет,
  кто прислал данные.
- **Проверяет и преобразует** их по дата-контракту источника: какое поле
  источника во что превращается, как разбирать даты, какие значения допустимы.
  Контракт настраивается в консоли без программирования.
- **Сохраняет исходные данные** как есть — до любых преобразований.
- **Сопоставляет** входящую карточку с существующими записями: по идентификатору
  клиента в источнике, а затем по точному совпадению реквизитов (ПИНФЛ, паспорт,
  ИНН).
- **Сливает по полям**: источник с более высоким уровнем доверия обновляет поле,
  остальные поля остаются за прежними источниками. При равном доверии и
  расхождении данные уходят на ручной разбор.
- **Хранит происхождение** каждого поля и версии записи.
- **Ведёт согласия** клиентов на обработку данных и оповещает об их изменении.
- **Отдаёт данные** потребителям: поиск Золотой записи, привязка внешних
  идентификаторов, проверка согласий.
- **Даёт интерфейсы людям**: консоль администратора (источники, контракты,
  конфликты, поиск) и фронт-офис (карточка «Клиент 360»).

Подробнее — [Возможности](features.md).

## Чего модуль не делает

Чтобы правильно спланировать внедрение, учтите границы текущей версии:

- **Не забирает данные сам.** Источник передаёт данные в платформу; коннекторов,
  которые читают базы данных или файлы источников, нет.
- **Не сопоставляет физлиц нечётко.** Совпадение определяется точным равенством
  реквизитов; опечатка в фамилии даст новую запись.
- **Не объединяет уже созданные Золотые записи.** Если два профиля одного
  человека уже существуют, слить их средствами платформы нельзя.
- **Не публикует события об изменении Золотых записей.** Потребители получают
  данные запросами.
- **Не обезличивает данные автоматически.** Механизмы токенизации и шифрования
  подготовлены, но к Золотой записи пока не подключены.

Полный список ограничений — на странице [Статус и ограничения](status.md).
