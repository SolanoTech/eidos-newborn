# Порядок подключения источника

Подключение источника — совместная работа двух сторон:

- **администратор платформы** регистрирует источник, настраивает дата-контракт
  и канал приёма;
- **интегратор источника** дорабатывает систему-источник, чтобы она
  передавала данные в нужном формате и обрабатывала ответы.

Ниже — порядок работ от первого разговора до промышленного потока. Пройдите
его для каждого источника и каждого типа сущности: физлица и юрлица
подключаются отдельно.

## Чек-лист

### 1. Оценить данные источника

- [ ] Сверьте поля источника с каталогом полей Золотой записи —
      [физлицо](../reference/fields-person.md), [юрлицо](../reference/fields-legal.md).
- [ ] Убедитесь, что источник может передать **все обязательные поля** целевой
      записи. Без них карточки будут отклоняться.
- [ ] Определите **идентификатор клиента** в источнике: стабильное значение,
      уникальное для каждого клиента. Оно станет внешним идентификатором записи.
- [ ] Выясните форматы: как записаны даты, как закодирован пол, есть ли
      справочные коды (гражданство, регион), как выглядят телефоны.
- [ ] Проверьте, совпадает ли написание ФИО с другими источниками: физлица
      сопоставляются по точному равенству. См. [Сопоставление](../concepts/matching.md).
- [ ] Оцените объём первичной загрузки и интенсивность изменений.

### 2. Принять решения

- [ ] **Уровень доверия** источника относительно уже подключённых. См.
      [Источники, доверие и контракты](../concepts/sources-and-contracts.md#уровень-доверия).
- [ ] **Канал**: REST — синхронный ответ по каждой карточке; Kafka — поток
      без ответа. См. [Передача по REST](rest.md) и [Передача через Kafka](kafka.md).
- [ ] **Порядок первичной загрузки** с учётом доверия. См.
      [Первичная загрузка и поток изменений](initial-load.md).

### 3. Зарегистрировать источник

- [ ] Заведите источник в реестре: код, название, токен, уровень доверия.
- [ ] Добавьте источник в таблицу источников ядра с тем же кодом и уровнем
      доверия.

См. [Регистрация источника](registration.md).

### 4. Описать дата-контракт

- [ ] Задайте поле-идентификатор.
- [ ] Опишите правило для каждого передаваемого поля: путь, целевое поле, тип,
      формат даты, проверки, таблицы значений.
- [ ] Покройте все обязательные поля целевой записи.

См. [Дата-контракт](data-contract.md).

### 5. Настроить канал

- [ ] REST: передайте интегратору адрес шлюза и токен.
- [ ] Kafka: настройте топик и группу потребителя шлюза для нужного типа
      сущности; передайте интегратору адрес брокера, топик и токен.

### 6. Передать интегратору

- [ ] Адрес шлюза или параметры Kafka.
- [ ] Токен — по защищённому каналу, не по почте и не в мессенджере.
- [ ] Спецификацию формата: какие поля, по каким путям, в каком формате
      ожидаются. Удобно выгрузить контракт:
      `GET /internal/api/v1/sources/{id}/contract`.
- [ ] Правила обработки ответов и повторов — [Ошибки, повторы, идемпотентность](errors.md).

### 7. Проверить и запустить

- [ ] Пройдите [проверку перед запуском](go-live.md) на тестовых данных.
- [ ] Выполните первичную загрузку.
- [ ] Включите поток изменений.

### 8. Сопровождать

- [ ] Следите за статистикой приёма на дашборде: доля отклонённых должна быть
      близка к нулю.
- [ ] Следите за очередью конфликтов: рост числа конфликтов с участием
      источника — повод пересмотреть доверие или контракт.
- [ ] Меняйте контракт при изменении формата источника и согласуйте изменения
      с интегратором заранее: контракт применяется сразу.
- [ ] Меняйте токен по регламенту и при подозрении на утечку.

## Кто что делает

| Шаг | Администратор платформы | Интегратор источника |
|---|---|---|
| Оценка данных | Даёт каталог полей и требования | Описывает данные источника |
| Решения | Уровень доверия, канал | Канал, объёмы, расписание |
| Регистрация | Реестр и ядро | — |
| Контракт | Настраивает | Проверяет соответствие своим данным |
| Канал | Настраивает топик или выдаёт адрес шлюза | Дорабатывает отправку |
| Проверка | Смотрит статистику, записи, конфликты | Отправляет тестовые данные |
| Сопровождение | Контракт, доверие, токен | Обработка ошибок, изменения формата |
