# Устранение неполадок

## Запуск стенда

| Симптом | Причина | Решение |
|---|---|---|
| `network frontend declared as external, but could not be found` | Не запущен стек Gravitee, который создаёт сеть `frontend` | Запустите Gravitee: `docker compose -f gravitee/docker-compose-apim.yml up -d`, — или создайте сеть вручную: `docker network create frontend` |
| Ошибка сборки `eidos-core` или `eidos-stage`: не найден `shared-library` | Модули клонированы не в те каталоги | Каталоги должны называться как в [быстром старте](../quickstart/stand.md#1-получите-исходный-код) |
| После `up --build` работает старая версия сервиса | Сборка упала, а compose оставил прежний контейнер | Соберите отдельно (`docker compose build <сервис>`), проверьте код выхода, затем `docker compose up -d --force-recreate <сервис>` |
| `port is already allocated` | Порт занят другим приложением | Освободите порт или поменяйте публикацию в файле переопределений; список — [Порты](../reference/ports.md) |
| Контейнер `eidos-cdi-ui` или `eidos-cdp-ui` сразу останавливается, в журнале `host not found in upstream "gateway"` | Шлюз Gravitee не запущен или не в сети `frontend` | Запустите Gravitee до консолей, затем `docker compose up -d eidos-cdi-ui eidos-cdp-ui` |
| Keycloak долго не становится `healthy` | Первый запуск: импорт realm и миграции базы | Подождите несколько минут; смотрите `docker compose logs keycloak` |

## Приём данных

| Симптом | Причина | Решение |
|---|---|---|
| `401 Invalid access token` | Неверный токен, токен сменили, источник удалён | Сверьте токен в консоли (**Источники → Изменить**) |
| `422 No PERSON data contract configured for source …` | Нет контракта для этого типа сущности | Создайте контракт; проверьте эндпоинт: физлица — `client-data`, юрлица — `legal-data` |
| `422 Client data failed contract validation: …` | Данные нарушают правила контракта | См. [Ошибки](../sources/errors.md#сообщения-шлюза) |
| `422 GoldenRecord validation failed …` | Контракт не покрывает обязательное поле или формат | Добавьте правило или регулярное выражение — [Дата-контракт](../sources/data-contract.md) |
| `422 eidos-core rejected record for source=…` и рост `unknownSource` в очереди | Источник не зарегистрирован в ядре | [Регистрация в ядре](../sources/registration.md#регистрация-в-ядре) |
| `422 eidos-core rejected record …`, в журнале ядра `duplicate key value violates unique constraint` на `gr_pinfl` | ПИНФЛ совпал с существующей записью при другом ФИО или дате рождения | Сверьте данные — [Сопоставление](../concepts/matching.md#физические-лица) |
| Карточка принята, но поле не изменилось | Правила слияния: тот же источник, меньшее или равное доверие | [Слияние и происхождение](../concepts/merge.md#правила-слияния) |
| Карточка принята, но поиск по идентификатору источника ничего не находит | Запись сопоставилась по реквизитам, связка не создалась | [Внешние идентификаторы](../consumers/external-ids.md) |
| В Золотой записи появились дубликаты клиента | Разное написание ФИО или даты рождения в источниках | Нормализуйте данные в источниках; см. [Сопоставление](../concepts/matching.md) |

## Kafka

| Симптом | Причина | Решение |
|---|---|---|
| Сообщения не обрабатываются, в журнале шлюза `No active Kafka config in DB` | Потребитель не включён | Консоль → **Kafka шлюза** или API |
| В журнале шлюза `Failed to start Gateway Kafka consumer` | Неверный адрес брокера, брокер недоступен | Адрес должен быть доступен **из контейнера шлюза**: на стенде `kafka:9092`, а не `localhost:19092` |
| `Skipping Kafka message …: Missing X-Access-Token` | В сообщении нет заголовка с токеном | Добавьте заголовок `X-Access-Token` к каждому сообщению |
| `Skipping Kafka message …` с другой причиной | Сообщение отклонено проверками | Причина — в конце строки; правила те же, что для REST |
| Счётчик отклонённых растёт быстрее, чем число ошибочных сообщений | Каждая повторная попытка обработки увеличивает счётчик | Ожидаемое поведение текущей версии |
| После смены группы потребителя заново обрабатываются старые сообщения | Новая группа читает топик с начала | Ожидаемое поведение; повторная обработка безопасна |

## Консоль

| Симптом | Причина | Решение |
|---|---|---|
| После входа разделы «Источники», «Конструктор», «Поиск» показывают «Не удалось загрузить…», Gravitee отвечает `401` | Не выполнен `setup_gravitee.py` или нет подписки приложения `eidos-console` | Запустите `python3 keycloak/setup_gravitee.py` — [Gravitee APIM](gravitee.md#настройка-маршрутов) |
| Те же разделы, ответ `502` или `504` | Шлюз Gravitee или API не развёрнут, сервис платформы недоступен | Проверьте `docker ps` для `gio_apim_gateway` и состояние API в консоли Gravitee |
| Те же разделы, ответ `401` от сервиса с текстом `Missing or invalid X-Admin-Token` | `ADMIN_TOKEN` в Gravitee не совпадает с `.env` | [Смена административного токена](gravitee.md#смена-административного-токена) |
| Дашборд, аудит-лог или согласия: `403 Access denied` | У пользователя нет роли `ADMIN` | Назначьте роль в Keycloak — [Keycloak](keycloak.md#пользователи) |
| Keycloak: `Invalid parameter: redirect_uri` | Адрес консоли не разрешён в клиенте `eidos-console` | [Адреса консолей](keycloak.md#адреса-консолей) |
| С другой машины консоль не открывает страницу входа | Консоль собрана с адресом Keycloak `http://localhost:8180` | [Адрес Keycloak в консолях](production.md#адрес-keycloak-в-консолях) |
| «Не удалось удалить источник» | У источника есть дата-контракт | [Удаление источника](../sources/registration.md#удаление-источника) |

## Ядро и ключи

| Симптом | Причина | Решение |
|---|---|---|
| Ядро не запускается, в журнале ошибка Flyway или `Schema-validation` | Миграция не прошла или схема не соответствует версии | Восстановите базу из копии; не меняйте схему `eidos_core` вручную |
| Приём физлиц и поиск по ПИНФЛ падают с `Key store operation failed` | OpenBao недоступен или запечатан | Проверьте OpenBao и токен ядра |
| `Cannot load blind index key` после перезапуска OpenBao на стенде | В режиме разработки KEK пересоздан, старый ключ индекса не разворачивается | [Восстановление стенда](openbao.md#стенд-режим-разработки) |
| В журнале ядра `Could not prepare fuzzy search for legal entities` | Нет прав на создание расширения `pg_trgm` | Выполните команды из сообщения пользователем с правами на базу |
| Состояние согласия в записях не обновляется | Ядро не читает события: разные топики, выключен потребитель, сервис согласий недоступен | Сверьте `EIDOS_CONSENTS_EVENTS_TOPIC` и `EIDOS_CONSENTS_EVENTS_ENABLED` в ядре и сервисе согласий; ищите `Consents service unreachable` в журнале ядра |

## eidos-stage

| Симптом | Причина | Решение |
|---|---|---|
| Ошибки подключения к MongoDB на `localhost:27017` в контейнере | Адрес задан переменной `SPRING_DATA_MONGODB_URI`, которую Spring Boot 4 игнорирует | Используйте `SPRING_MONGODB_URI` |
| Ошибка при сохранении поля контракта с новым типом | В существующей базе не обновилось ограничение типов | Перезапустите `eidos-stage`: стартовый скрипт обновит ограничение; см. журнал `Registry schema ready` |

## Где искать причину

1. Ответ API — поле `detail`.
2. Журнал сервиса, на котором остановилась карточка:
   `docker compose logs --since 10m <сервис>`.
3. Состояние инфраструктуры: `docker compose ps`.
4. [Мониторинг и диагностика](monitoring.md) — полезные строки журналов.
