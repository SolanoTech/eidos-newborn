# Keycloak

Keycloak отвечает за вход в консоли. Пользователи заводятся в нём, консоли
получают токены по OpenID Connect, а `eidos-cdi-ui-backend` и Gravitee
проверяют подпись токенов.

## Realm `eidos`

Realm импортируется из `keycloak/realm-eidos.json` при **первом** запуске
Keycloak (`--import-realm`). Повторные запуски файл не перечитывают: правки
после первого запуска вносятся в консоли администрирования Keycloak или через
его API.

| Объект | Настройки на стенде |
|---|---|
| Realm `eidos` | Срок жизни access-токена — 5 минут; сессия завершается после 30 минут бездействия; `sslRequired: none`; самостоятельная регистрация выключена |
| Роль `ADMIN` | Единственная роль realm; нужна для работы в консолях |
| Клиент `eidos-console` | Публичный, Authorization Code + PKCE (S256); адреса возврата `http://localhost:8088/*`, `:8089/*`, `:5173/*`, `:5174/*` |
| Клиент `eidos-m2m` | Конфиденциальный, client credentials; для межсервисных вызовов; секрет `eidos-m2m-secret-change-me` |
| Пользователь `admin` | Пароль `admin`, роль `ADMIN` |

Консоль администрирования Keycloak на стенде — <http://localhost:8180/admin>,
вход `admin` / `admin` (учётная запись первоначального администратора задаётся
переменными `KC_BOOTSTRAP_ADMIN_USERNAME` и `KC_BOOTSTRAP_ADMIN_PASSWORD`).

## Пользователи

Чтобы дать сотруднику доступ к консолям:

1. Keycloak → realm **eidos** → **Users** → **Add user**; задайте логин.
2. Вкладка **Credentials** → задайте временный пароль.
3. Вкладка **Role mapping** → **Assign role** → роль `ADMIN`.

Логин пользователя записывается в аудит-лог при операциях с согласиями.

!!! warning "Роль проверяется не на всех путях"
    Административные пути консолей проходят через Gravitee, который проверяет
    подпись токена, но не роль. Пользователь realm `eidos` без роли `ADMIN`
    получит доступ к источникам, контрактам и конфликтам. Заводите в realm
    только сотрудников, которым нужна полная роль. См.
    [Модель доступа](../concepts/access-model.md#контур-2-пользователи-консолей).

Вместо локальных учётных записей можно подключить корпоративный каталог (LDAP,
Active Directory) или внешнего провайдера через механизмы Keycloak: User
Federation и Identity Providers. Роль `ADMIN` назначайте через сопоставление
групп.

## Адреса консолей

Клиент `eidos-console` принимает возврат только на перечисленные адреса. При
установке на сервер:

1. **Clients** → `eidos-console` → **Settings**.
2. **Valid redirect URIs** — адреса консолей, например
   `https://cdi.example.uz/*` и `https://office.example.uz/*`.
3. **Valid post logout redirect URIs** — те же адреса.
4. **Web origins** — `+` (разрешить источники из адресов возврата) или
   адреса консолей явно.

Удалите адреса `localhost`, если они не нужны.

Сами консоли знают адрес Keycloak из сборки — см.
[Адрес Keycloak в консолях](production.md#адрес-keycloak-в-консолях).

## Проверка токенов сервисами

| Кто проверяет | Как | Откуда берёт ключи |
|---|---|---|
| `eidos-cdi-ui-backend` | Подпись токена, роль `ADMIN` из `realm_access.roles`; имя пользователя — `preferred_username` | `SPRING_SECURITY_OAUTH2_RESOURCESERVER_JWT_JWK_SET_URI`, на стенде `http://keycloak:8180/realms/eidos/protocol/openid-connect/certs` |
| Gravitee | Подпись токена (RS256) и что `azp` = `eidos-console` | Тот же адрес JWKS, задаётся в JWT-плане |

Сервисы проверяют подпись по ключам realm, но не сверяют издателя токена
(`iss`). Поэтому внутренний адрес Keycloak (`http://keycloak:8180`) может
отличаться от адреса, по которому его видят браузеры.

## Производственный режим

На стенде Keycloak работает в режиме разработки (`start-dev`). Для сервера:

- запуск командой `start`;
- `KC_HOSTNAME` — публичный адрес Keycloak;
- TLS на Keycloak или на обратном прокси перед ним (`KC_PROXY_HEADERS=xforwarded`
  при работе за прокси);
- собственные учётные данные первоначального администратора;
- в realm `eidos`: `sslRequired` — `external`, удалить пользователя `admin`,
  сменить секрет клиента `eidos-m2m`;
- база Keycloak — отдельная база `keycloak` в PostgreSQL; включите её в
  [резервное копирование](backup.md).

Подробно — документация Keycloak по развёртыванию в производственном режиме.
