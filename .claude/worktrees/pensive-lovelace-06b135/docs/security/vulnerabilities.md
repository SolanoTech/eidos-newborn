# Сообщить об уязвимости

Eidos обрабатывает персональные данные, поэтому сообщения об уязвимостях
разбираются в приоритетном порядке. Полная политика — файл
[`SECURITY.md`](https://github.com/SolanoTech/eidos-infrastructure/blob/main/SECURITY.md)
в каждом репозитории платформы.

## Как сообщить

**Не открывайте публичный issue и не присылайте pull request с
исправлением** до выпуска исправления: уязвимость в системе с персональными
данными не должна становиться публичной раньше времени.

Сообщите приватно: в репозитории на GitHub откройте вкладку **Security** →
**Report a vulnerability**.

## Что приложить

- затронутый компонент и версию — тег или хеш коммита;
- шаги воспроизведения — короткий сценарий лучше длинного;
- оценку последствий: какие данные или операции затронуты;
- предложение по исправлению, если есть.

## Чего ждать

| Этап | Срок |
|---|---|
| Подтверждение получения | 3 рабочих дня |
| Первичная оценка и класс серьёзности | 10 рабочих дней |
| Исправление критичных уязвимостей | По согласованию, приоритетно |

Если вы не против, автор находки указывается в примечаниях к выпуску.

Исправления выпускаются для последнего минорного выпуска; более ранние версии
обновляются по отдельной договорённости.

## Просьба

Не тестируйте чужие установки Eidos и данные, которые вам не принадлежат.
Разверните собственный стенд — см. [Быстрый старт](../quickstart/stand.md).

Известные ограничения безопасности текущей версии перечислены открыто на
странице [Статус и ограничения](../intro/status.md#безопасность) — сообщать о
них отдельно не нужно.
