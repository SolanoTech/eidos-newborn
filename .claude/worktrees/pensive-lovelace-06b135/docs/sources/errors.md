# Ошибки, повторы, идемпотентность

## Где возникают ошибки

Карточка может быть отклонена на трёх ступенях. Ответ всегда имеет вид
`{"detail": "…"}`, а по тексту сообщения понятно, на какой ступени произошёл
отказ:

| Ступень | Как узнать | Сырьё сохранено |
|---|---|---|
| Шлюз — токен и контракт | `401` или `422` с текстом из таблицы ниже | Нет |
| `eidos-stage` — преобразование и формат Золотой записи | `422`, текст содержит `for source=<код>` | Да |
| Ядро | `422` с текстом `eidos-core rejected record for source=<код>` | Да |

## Сообщения шлюза

| Код | Сообщение | Причина | Что делать |
|---|---|---|---|
| `401` | `Missing X-Access-Token` | Нет заголовка с токеном | Добавьте заголовок |
| `401` | `Invalid access token` | Токен неизвестен: опечатка, токен сменили или источник удалён | Сверьте токен с администратором платформы |
| `422` | `No PERSON data contract configured for source <код>` (или `LEGAL_ENTITY`) | Для источника нет контракта на этот тип сущности | Администратор должен описать контракт; проверьте, тот ли эндпоинт вы вызываете |
| `422` | `Malformed client-data body: …` | Тело не является JSON-объектом | Исправьте формирование запроса |
| `422` | `Client data failed contract validation: …` | Нарушены правила контракта; список нарушений — через `; ` | Исправьте данные — см. ниже |

Нарушения контракта:

| Нарушение | Значение |
|---|---|
| `missing required field: <путь>` | Обязательное поле не пришло или пустое, значения по умолчанию нет |
| `value '<значение>' is not allowed for field: <путь>` | Значения нет в таблице значений поля |
| `field '<путь>' does not match required format` | Значение не совпало с регулярным выражением |
| `field '<путь>' is not a valid date` | Дата не разбирается по формату из контракта |
| `field '<путь>' is not a valid integer` | Не целое число |
| `field '<путь>' is not a valid boolean` | Не `true` и не `false` |
| `field '<путь>' must be an array` | Для поля типа `ARRAY` или `STRUCT` пришёл не массив |

Пример:

```json
{"detail":"Client data failed contract validation: missing required field: passport.number; field 'phone' does not match required format"}
```

## Сообщения eidos-stage

| Сообщение | Причина | Что делать |
|---|---|---|
| `GoldenRecord validation failed for source=<код>: …` | Данные прошли контракт, но не соответствуют требованиям Золотой записи; список нарушений — через `; ` | Исправьте данные; администратору — дополнить контракт правилами и выражениями, чтобы такие ошибки ловил шлюз |
| `Mapping to GoldenRecord failed for source=<код>` | Значение не удалось привести к типу поля: число вне диапазона, неверная структура массива, значение по умолчанию в неверном формате, таблица значений даёт недопустимое значение | Сверьте данные и контракт; подробности — в журнале `eidos-stage` |
| `Message has no 'data' for source=<код>` | В теле нет поля `data` | Передавайте данные внутри `data` |
| `No data contract configured for source=<код> type=<тип>` | Контракт удалили, пока карточка была в пути | Повторите после восстановления контракта |
| `Failed to persist raw data for source=<код>` | MongoDB недоступна | Повторите позже |

Нарушения Золотой записи называют поле по имени свойства и описывают
требование, например:

```text
GoldenRecord validation failed for source=crm: grPinfl PINFL must be exactly 14 digits; grCitizenship must not be blank
```

## Ошибки ядра

Если ядро отказало, источник получает одно и то же сообщение
`eidos-core rejected record for source=<код>` — причину знает только журнал
ядра. Частые причины:

| Причина | Признак в журнале `eidos-core` | Что делать |
|---|---|---|
| Источник не зарегистрирован в ядре | `Unknown source '<код>' — writing tentative and rejecting request` | Зарегистрируйте источник в ядре — [Регистрация источника](registration.md#регистрация-в-ядре) |
| ПИНФЛ совпал с существующей записью при другом ФИО или дате рождения | Нарушение уникальности `gr_pinfl` | Сверьте данные с существующей записью — [Сопоставление](../concepts/matching.md#физические-лица) |
| Ядро недоступно | В журнале `eidos-stage` — `I/O error while calling eidos-core` | Повторите позже |

!!! warning "Повторы при неизвестном источнике"
    Каждая карточка от источника, которого нет в ядре, добавляет запись в
    очередь разбора. Повторы таких карточек множат записи в очереди. Если
    получаете отказ ядра, не повторяйте отправку бесконечно — обратитесь к
    администратору платформы.

## Когда повторять

| Ответ | Повторять? |
|---|---|
| `200` | Нет |
| `401` | Нет — сначала исправьте токен |
| `422` от шлюза | Нет — сначала исправьте данные или контракт |
| `422` с `GoldenRecord validation failed` или `Mapping to GoldenRecord failed` | Нет — сначала исправьте данные или контракт |
| `422` с `Failed to persist raw data` | Да, с паузой |
| `422` с `eidos-core rejected record` | Несколько раз с нарастающей паузой; если не проходит — к администратору платформы |
| `5xx`, таймаут, разрыв соединения | Да, с нарастающей паузой |

## Идемпотентность

Повторная отправка той же карточки **безопасна**:

- карточка с уже известным идентификатором клиента сопоставится с той же
  Золотой записью;
- карточка от того же источника не меняет его собственных значений;
- значения, которые за это время обновил более надёжный источник, повтор не
  откатит.

Поэтому при таймауте или разрыве соединения повторяйте запрос, не выясняя,
дошёл ли первый. Повторы оставляют следы: каждая попытка сохраняется в сырьё и
увеличивает счётчик принятых.

Особенности:

- если первая карточка сопоставилась с записью по реквизитам, а не по
  идентификатору, повтор тоже сопоставится по реквизитам — результат тот же;
- при равном доверии каждая повторная карточка с расхождением создаёт новую
  запись в очереди конфликтов.
