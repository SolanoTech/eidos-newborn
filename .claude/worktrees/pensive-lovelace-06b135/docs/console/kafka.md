# Kafka шлюза

**Консоль администратора → Kafka шлюза** — настройка потребителя, через
который шлюз читает карточки физлиц из Kafka. Как устроен приём из Kafka —
[Передача через Kafka](../sources/kafka.md).

## Поля

| Поле | Что указать | По умолчанию |
|---|---|---|
| Bootstrap servers | Адреса брокеров через запятую — так, как их видит контейнер шлюза. На стенде — `kafka:9092` | — |
| Топик | Топик с карточками физлиц | `client-data` |
| Consumer group | Группа потребителя шлюза | `eidos-gateway` |
| Консьюмер включён | Читать ли топик | включён |

**Сохранить и перезапустить** применяет настройки сразу: шлюз останавливает
потребителя и запускает его с новыми параметрами. Сообщение
«Конфигурация сохранена, консьюмер перезапущен» означает, что настройки
записаны; ошибки подключения к брокеру видны только в журнале шлюза.

## Что учесть

- **Новая группа читает топик с начала.** Если сменить группу на новую, шлюз
  заново обработает все сообщения, которые хранит брокер. Для уже
  обработанных карточек это безопасно, но займёт время.
- **Выключение останавливает приём из топика для всех источников.** Сообщения
  остаются в брокере и будут прочитаны после включения.
- **Канал юрлиц** настраивается только через API — параметр
  `entityType: LEGAL_ENTITY`, см. [Передача через Kafka](../sources/kafka.md#через-api).
- **Аутентификация к брокеру** (TLS, SASL) не поддерживается.

## Проверить

```bash
docker compose logs eidos-gateway --since 5m | grep -i "kafka consumer"
```

Строка `Gateway Kafka consumer started: entityType=PERSON topic=… group=… servers=…`
означает, что потребитель запущен. `No active Kafka config in DB` — ни один
потребитель не включён.
