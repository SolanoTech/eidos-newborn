# Персональные данные

Платформа обрабатывает персональные данные клиентов. Эта страница помогает
оператору платформы ответить на вопросы: где хранятся данные, в каком виде,
сколько и как их найти и удалить по запросу.

## Где хранятся

| Место | Что | Вид | Срок хранения |
|---|---|---|---|
| `eidos_core.golden_record` | Золотые записи физлиц: ФИО, ПИНФЛ, паспорт, телефон, e-mail, адреса | Открыто | Не ограничен |
| `eidos_core.golden_record_archive` | Состояние записи после каждого изменения | Открыто | Не ограничен |
| `eidos_core.tentative_golden_record` | Входящие карточки в очереди разбора | Открыто | До решения стюарда |
| `eidos_core.golden_record_external_id` | Идентификаторы клиента в системах-источниках | Открыто | Не ограничен |
| `eidos_core.legal_entity_*` | Записи юрлиц, в том числе ФИО руководителя, ПИНФЛ учредителей | Открыто | Не ограничен |
| `eidos_core.golden_record` (`pd_bi_*`) | Слепой индекс | HMAC, необратимо без ключа | Вместе с записью |
| `eidos_core.vault` | Ключи и токены | Шифрование | Не используется для Золотой записи в текущей версии |
| `eidos_stage.raw_client_data` (MongoDB) | Сырьё: всё, что прислал источник, включая поля вне контракта | Открыто | **Не ограничен** |
| `consents.consents` | Согласия: идентификатор клиента, тип, даты | Открыто | Не ограничен |
| `eidos_ui_backend.audit_events` | Журнал: логин оператора, действие, идентификатор клиента | Открыто | Не ограничен |
| Журналы сервисов | Идентификаторы клиентов, фрагменты значений в сообщениях об ошибках | Открыто | По настройке журналирования |
| Kafka | Карточки и события в топиках | Открыто | По настройке хранения топиков |
| Выгрузки из консолей | JSON-экспорт карточек, CSV аудит-лога | На компьютере пользователя | Вне контроля платформы |
| Резервные копии | Всё перечисленное | Как настроено | По регламенту |

## Минимизация

- **Сырьё** хранит всё, что прислал источник, даже поля без правила в
  контракте. Договоритесь с источниками не передавать лишнего и задайте срок
  хранения сырья TTL-индексом — см. [Базы данных](../operations/databases.md#mongodb).
- **Топики Kafka** — задайте срок хранения (`retention.ms`), достаточный для
  обработки, но не больше.
- **Журналы** — ограничьте срок хранения и доступ.

## Найти данные клиента

По идентификатору Золотой записи `GR_<uuid>`:

```sql
-- eidos_core
SELECT * FROM golden_record                WHERE gr_client_id = 'GR_<uuid>';
SELECT * FROM golden_record_archive        WHERE gr_client_id = 'GR_<uuid>';
SELECT * FROM golden_record_external_id    WHERE gr_client_id = 'GR_<uuid>';
SELECT * FROM golden_record_field_meta     WHERE gr_client_id = 'GR_<uuid>';
SELECT * FROM tentative_golden_record      WHERE gr_client_id = 'GR_<uuid>'
                                              OR gr_pinfl = '<ПИНФЛ>';

-- consents: идентификатор без префикса GR_
SELECT * FROM consents WHERE client_uuid = '<uuid>';
```

Сырьё ищется по пути идентификатора клиента в данных конкретного источника:

```javascript
// MongoDB, база eidos_stage
db.raw_client_data.find({ source: "bank-1", "data.client_id": "CL-778812" })
```

Путь (`data.client_id`) зависит от контракта источника — возьмите его из поля
«идентификатор» контракта. Связки «источник — идентификатор» — в таблице
`golden_record_external_id`.

Проверьте также поля юрлиц: ФИО руководителя и учредителей
(`legal_entity_record.gr_director_name`, `gr_founders`).

## Удалить данные клиента

Штатной операции удаления в текущей версии нет. Если удаление требуется по
закону или по запросу клиента, выполните его вручную, по согласованию с
ответственным за обработку персональных данных:

1. Убедитесь, что источники больше не передают данные клиента, — иначе запись
   появится снова.
2. Удалите строки из таблиц `eidos_core` в порядке зависимостей: связки,
   происхождение, архив, незавершённые записи, затем сама запись.
3. Удалите или обезличьте согласия, если закон не требует их хранить.
4. Удалите документы сырья в MongoDB.
5. Учтите копии: резервные копии, журналы, выгрузки.

Внимание: удаление записи нарушает сквозную историю, и восстановить её нельзя.
Сделайте резервную копию перед удалением и зафиксируйте факт и основание
удаления.

## Права оператора консоли

Пользователь консоли с ролью `ADMIN` видит профили всех клиентов, токены
источников и может выдавать и отзывать согласия. Выдавайте доступ только тем,
кому он нужен для работы, и регулярно пересматривайте список пользователей в
Keycloak.
