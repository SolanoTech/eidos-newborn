# Сообщения и события Kafka

## Топики

| Топик | Кто пишет | Кто читает | Настройка |
|---|---|---|---|
| Карточки физлиц, на стенде `client-data` | Системы-источники | `eidos-gateway` | База шлюза, [API](api/gateway-admin.md) или консоль |
| Карточки юрлиц, на стенде `legal-data` | Системы-источники | `eidos-gateway` | База шлюза, [API](api/gateway-admin.md) |
| `consent-events` | `eidos-consents` | `eidos-core`, системы-потребители | Переменная `CONSENT_EVENTS_TOPIC` |

Имена топиков карточек выбираются при настройке каналов шлюза.

## Карточки источников

| Часть сообщения | Содержимое |
|---|---|
| Ключ | Не используется платформой; рекомендуется идентификатор клиента в источнике |
| Заголовок `X-Access-Token` | Токен источника, UTF-8 |
| Значение | JSON в UTF-8 |

```json
{
  "data": {
    "client_id": "CRM-000123",
    "person": {"last_name": "Каримов", "first_name": "Алишер"},
    "…": "…"
  }
}
```

- `data` — данные в формате источника, как их описывает дата-контракт.
- `source` указывать не нужно: шлюз записывает код источника из токена.
- Тип сущности определяется топиком.

Обработка ошибок — [Передача через Kafka](../sources/kafka.md#что-происходит-с-ошибочными-сообщениями).

## consent-events

| Часть сообщения | Содержимое |
|---|---|
| Ключ | `client_uuid` строкой — события одного клиента идут в одну партицию |
| Заголовки | Нет |
| Значение | JSON в UTF-8 |

```json
{
  "event_type": "new",
  "client_uuid": "5f0c2b1e-8a4d-4c55-9a8e-2b7d4f1c9e10",
  "type": "pd",
  "start_date": "2026-10-01",
  "end_date": "2027-03-30"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `event_type` | `new` или `expired` | `new` — согласие выдано; `expired` — у клиента не осталось действующего согласия этого типа |
| `client_uuid` | UUID | Идентификатор Золотой записи физлица без префикса `GR_` |
| `type` | строка | Код типа согласия — [Перечисления](enums.md#типы-согласий) |
| `start_date` | дата | Начало действия согласия, о котором событие |
| `end_date` | дата | Окончание действия включительно |

Гарантии:

- `new` публикуется после сохранения согласия; при недоступности брокера
  событие теряется;
- `expired` публикуется ежедневным проходом — одно событие на пару
  «клиент + тип» в день, с датами самого позднего из закончившихся согласий;
- доставка не меньше одного раза.

Семантика и ограничения — [События о согласиях](../consumers/consent-events.md).
