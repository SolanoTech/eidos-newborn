# Конструктор контракта

**Консоль администратора → Конструктор контракта** — настройка правил, по
которым данные источника превращаются в Золотую запись. Что такое контракт и
как выбирать атрибуты правил — [Дата-контракт](../sources/data-contract.md).

## Выбрать контракт

В верхней панели выберите:

- **источник** — по коду;
- **тип сущности** — «Физлица» или «Юрлица». У источника может быть по
  контракту на каждый тип.

Под панелью — номер версии контракта и число правил. Если контракта ещё нет,
список пуст: контракт создастся при первом сохранении.

## Задать поле-идентификатор

В блоке «Идентификация клиента в источнике» (для юрлиц — «юрлица») укажите
путь к идентификатору клиента в данных источника, например `client_id`, и
нажмите **Сохранить**. Без идентификатора ядро отклоняет карточки.

## Добавить правило

1. Нажмите **+ Поле**.
2. Заполните окно:

    | Поле окна | Что указать |
    |---|---|
    | Поле источника (dot-path) | Путь к значению в данных источника, например `person.phone` |
    | Целевое поле Golden Record | Поле записи из списка; обязательные отмечены «(обяз.)» |
    | Тип | `STRING`, `DATE`, `INTEGER`, `BOOLEAN` или `GENDER` |
    | Формат даты | Для типа `DATE`, например `dd.MM.yyyy` |
    | Regex валидации | Регулярное выражение для проверки на шлюзе, например `^998\d{9}$` |
    | Value-map | Таблица значений в виде `1→M, 2→F` (можно `1=M, 2=F`), пары через запятую |
    | Значение по умолчанию | Подставляется, если источник не прислал значение |
    | Обязательное поле | Отклонять карточку без значения |

3. Нажмите **Сохранить**. Консоль сообщит, что контракт получил новую версию.

Если выбрано несуществующее целевое поле, сохранение не пройдёт с сообщением
`Unknown Golden Record field`.

## Изменить или удалить правило

У каждого правила в списке есть кнопки **Изменить** и **Удалить**. Любое
изменение увеличивает номер версии контракта.

!!! warning "Изменения действуют сразу"
    Шлюз и `eidos-stage` читают контракт при каждой карточке. Новое
    обязательное правило начнёт отклонять карточки без этого поля сразу после
    сохранения. Согласуйте правки с командой источника заранее.

## Ограничения экрана

- Типы `ARRAY` и `STRUCT` — для телефонов и учредителей юрлица — в списке
  типов отсутствуют. Такие правила создаются через API, см.
  [API eidos-stage](../reference/api/stage.md#дата-контракт); в консоли они
  отображаются, и их можно удалить.
- Таблица значений вводится одной строкой, пары разделяются запятой, поэтому
  значения не могут содержать запятых. Такие таблицы задавайте через API.
- Прежние версии контракта не хранятся. Чтобы сохранить текущее состояние перед
  большой правкой, выгрузите контракт через API:
  `GET /internal/api/v1/sources/{id}/contract?entityType=PERSON`.

## Проверить контракт

После правки отправьте тестовую карточку через REST — шлюз вернёт понятные
нарушения, если правило настроено неверно. См.
[Проверка перед запуском](../sources/go-live.md).
