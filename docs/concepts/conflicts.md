# Незавершённые записи и конфликты

Некоторые данные платформа не может уверенно привязать к Золотой записи. Такие
данные не теряются и не применяются автоматически — они попадают в очередь
ручного разбора как **незавершённые записи** (tentative). У физлиц и юрлиц
очереди раздельные.

## Причины

| Причина | Код | Когда возникает | Что сохраняется |
|---|---|---|---|
| Неизвестный источник | `UNKNOWN_SOURCE` | Данные пришли от источника, которого нет в таблице источников ядра | Вся входящая карточка; ссылки на Золотую запись нет |
| Конфликт при равном доверии (серая зона) | `GREY_ZONE_CONFLICT` | Источник с тем же уровнем доверия, что у владельца поля, прислал другое значение | Вся входящая карточка и ссылка на Золотую запись |

В обоих случаях сохраняется **входящий снимок** — значения, которые предложил
источник. Текущие значения остаются в самой Золотой записи, поэтому при разборе
их можно сравнить поле за полем.

Конфликт по нескольким полям одной карточки даёт одну запись в очереди, а не
несколько.

## Решения

| Действие | Код | Результат |
|---|---|---|
| Оставить текущие | `KEEP_CURRENT` | Золотая запись не меняется, запись удаляется из очереди |
| Принять входящие | `ACCEPT_INCOMING` | В Золотую запись переносятся все непустые значения снимка, отличающиеся от текущих; эти поля переходят к источнику снимка; версия растёт, состояние уходит в архив; запись удаляется из очереди |
| Отклонить | `REJECT` | Ничего не применяется, запись удаляется из очереди |
| Отложить | — | Только в консоли: окно закрывается, запись остаётся в очереди |

!!! warning "«Принять входящие» не ограничивается конфликтными полями"
    Применяются все отличающиеся непустые значения снимка, в том числе в полях,
    которые принадлежат источникам с более высоким доверием. Перед принятием
    просмотрите весь список расхождений.

Для `UNKNOWN_SOURCE` доступно только отклонение. Чтобы данные попали в
платформу, зарегистрируйте источник в ядре и отправьте их заново, а запись в
очереди отклоните. Принять запись нельзя: у неё нет Золотой записи, с которой
можно слить данные, и нет уровня доверия источника.

Для `ACCEPT_INCOMING` источник снимка должен быть зарегистрирован в ядре —
иначе ядро вернёт ошибку `422`.

## Как устроена очередь

- Новые записи — сверху; консоль показывает 20 последних, API отдаёт
  постранично по 20.
- Счётчики очереди — всего, серая зона, неизвестный источник — отдаёт
  `GET /api/v1/internal/tentative/count` (у юрлиц `tentative-legal/count`).
- Решение необратимо: удалённая из очереди запись не восстанавливается.
  Значения, перенесённые при принятии, можно найти в архиве Золотой записи.
- Кто и когда принял решение, в текущей версии не фиксируется: аудит-лог
  консоли эти действия не записывает.

## Как разбирать

Практические шаги — в руководстве [Очередь конфликтов](../console/conflicts.md).
Общие ориентиры:

- **Много конфликтов от одной пары источников** — признак того, что им
  выставлено равное доверие без необходимости или один из них присылает
  неполные карточки. Пересмотрите уровни доверия.
- **Поток `UNKNOWN_SOURCE`** почти всегда значит, что источник завели в реестре
  и выдали ему токен, но забыли добавить в ядро.
- Доля конфликтов отражается на дашборде показателем «Auto-merge rate».
