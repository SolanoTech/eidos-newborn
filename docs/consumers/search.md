# Поиск Золотой записи

Системы, которым нужны данные о клиенте, ищут Золотую запись через внешний API
шлюза. Для доступа нужен токен: потребителю, как и источнику, заводят запись в
реестре источников — см. [Регистрация источника](../sources/registration.md).

| Поиск | Внешний API шлюза | Внутренний API ядра |
|---|---|---|
| Точный по реквизитам физлица | да | да |
| По идентификатору в системе-источнике | да | да |
| Структурный по нескольким критериям | — | да |
| По подстроке | — | да |
| Юрлица: по ИНН, по названию | — | да |

Внутренний API ядра не защищён аутентификацией и доступен только системам во
внутренней сети платформы — см. [API eidos-core](../reference/api/core.md).
Системам извне доступен только внешний API шлюза.

## Точный поиск физлица

```http
GET /api/v1/external/golden-records/search/accurate?lastName=Каримов&firstName=Алишер&birthDate=1990-04-15&pinfl=31504900120034
X-Access-Token: <токен>
```

| Параметр | Обязателен | Описание |
|---|---|---|
| `lastName` | да | Фамилия |
| `firstName` | да | Имя |
| `birthDate` | да | Дата рождения, `yyyy-MM-dd` |
| `pinfl` | одно из двух | ПИНФЛ |
| `passport` | одно из двух | Серия и номер паспорта, например `AB1234567` |

Правило то же, что при [сопоставлении](../concepts/matching.md): точное
совпадение всех четырёх значений, без приведения регистра и пробелов. Если
переданы и ПИНФЛ, и паспорт, используется ПИНФЛ.

| Ответ | Значение |
|---|---|
| `200` | Золотая запись |
| `404` `{"detail":"Golden Record Not Found"}` | Записи нет |
| `422` `{"detail":"Passport or PINFL required for accurate search"}` | Не передан ни ПИНФЛ, ни паспорт |
| `500` | Не передан обязательный параметр или дата в неверном формате; причина — в поле `detail` |

## По идентификатору в источнике

```http
GET /api/v1/external/golden-records/search/source-id?source=bank-1&source_id=CL-778812
X-Access-Token: <токен>
```

| Параметр | Описание |
|---|---|
| `source` | Код источника, в котором клиент известен под этим идентификатором |
| `source_id` | Идентификатор клиента в этом источнике |

Код источника не обязан совпадать с вашим: можно найти клиента по его номеру в
любой системе, если связка существует.

| Ответ | Значение |
|---|---|
| `200` | Золотая запись |
| `404` `{"detail":"Source Not Found"}` | Источника с таким кодом нет в ядре |
| `404` `{"detail":"Golden Record Not Found"}` | Связки нет |

!!! note "Связка есть не всегда"
    Связка создаётся, когда источник создаёт запись, или при явной привязке.
    Если карточка источника сопоставилась с уже существующей записью по
    реквизитам, связка для него не создаётся — поиск по его идентификатору не
    найдёт запись. См. [Внешние идентификаторы](external-ids.md).

## Формат ответа

Ответ — Золотая запись физлица. Имена полей — имена свойств: `grFirstName`, а
не `GR_FirstName` (см. [Модель данных](../concepts/data-model.md#три-формы-имени-поля)).

```json
{
  "grClientId": "GR_5f0c2b1e-8a4d-4c55-9a8e-2b7d4f1c9e10",
  "version": 1,
  "createdAt": "2026-10-04T10:15:30.481233",
  "updatedAt": "2026-10-04T11:02:12.090114",
  "grMobilePhoneMain": "998935554433",
  "grContactsEmail": "a.karimov@bank.example.uz",
  "grFirstName": "Алишер",
  "grMiddleName": "Бахтиёрович",
  "grLastName": "Каримов",
  "grPinfl": "31504900120034",
  "grGender": "M",
  "grBirthDate": "1990-04-15",
  "grCitizenship": "Узбекистан",
  "grCitizenshipId": "860",
  "grDocPassData": "AB1234567",
  "grDocIssuedBy": "ОВД Мирзо-Улугбекского района",
  "grDocIssuedById": "26283",
  "grDocIssuedDate": "2015-05-20",
  "grAddrPermanentAddress": null,
  "…": "…"
}
```

- Пустые поля приходят со значением `null`.
- Даты — `yyyy-MM-dd`, метки времени — `yyyy-MM-ddTHH:mm:ss.ffffff` без часового
  пояса, по часам сервера.
- Пол — `M` или `F`.
- `version` растёт при каждом изменении данных записи.

Кроме полей записи, в ответе есть служебные поля: состояние согласия
(`pdConsentActive`, `pdConsentValidTo`, `pdConsentCheckedAt`) и слепой индекс
(`pdBiIdentity`, `pdBiIdentityDoc`, `pdBiPinfl`, `pdBiKeyVersion`). Не
используйте их в интеграции: это внутренние поля, их состав может измениться.
Для решений о согласии используйте [проверку согласия](consent-check.md).

## Внутренний поиск

Системы внутри периметра платформы могут обращаться к ядру напрямую:

- `GET /api/v1/internal/golden-records/search/structured` — по ПИНФЛ (целиком),
  паспорту, фамилии, имени, отчеству, телефону (по подстроке), постранично;
- `GET /api/v1/internal/golden-records/search?query=…` — нечёткий поиск по ФИО;
- `GET /api/v1/internal/golden-records/{id}` — запись по идентификатору;
- `GET /api/v1/internal/legal-records/search/inn?inn=…` — мерчант по ИНН;
- `GET /api/v1/internal/legal-records/search/name?query=…` — мерчанты по
  названию с ранжированием по сходству.

Параметры и форматы — [API eidos-core](../reference/api/core.md).

## Нечёткий поиск

Нечёткий поиск клиентов и мерчантов обслуживает OpenSearch. Платформа ведёт два
индекса — отдельно по клиентам и по мерчантам, — и держит в них только то, по
чему ищут: ФИО клиента, полное и краткое наименование мерчанта. ПИНФЛ, паспорт,
телефон и адреса в индекс не попадают: их ищут точно, и за это отвечает
PostgreSQL.

### Что умеет

**Сводит кириллицу и латиницу.** Анализатор переводит кириллицу в узбекскую
латиницу (`ғ` → `g'`, `ў` → `o'`, `ш` → `sh` …), поэтому «Каримов», «КАРИМОВ» и
«Karimov» дают один и тот же результат.

**Прощает опечатки.** Допустимое расхождение подбирается по длине слова, так что
«Saidva Gulnora» находит «Саидову Гульнору».

**Игнорирует организационно-правовые формы** у мерчантов: `ООО`, `MCHJ`, `АО`,
`LLC`, `LTD`, `ЧП`, `ЯТТ` и ещё три десятка. «ООО "Оазис Маркет"», «Oazis Market
MCHJ» и «ОАЗИС МАРКЕТ МЧЖ» сходятся в `oazis market`.

### Ограничения

**Запрос короче трёх символов отклоняется** — он вернул бы половину базы.

**Клиенты без действующего согласия не находятся.** Когда согласие
заканчивается, платформа обезличивает запись и удаляет её документ из индекса.
Точный поиск по ПИНФЛ при этом продолжает работать: чтобы найти такого человека,
надо уже знать его номер. Подробнее — [Защита персональных
данных](../concepts/data-protection.md).

**Индекс догоняет базу, а не совпадает с ней секунда в секунду.** Документ
обновляется после фиксации изменений, а при недоступности поисковой подсистемы
отстаёт до ближайшего догоняющего прохода. Для сверки «есть ли вообще такой
клиент» пользуйтесь точным поиском.

### Для внешних потребителей

`GET /api/v1/external/golden-records/search/fuzzy?query=…&limit=…`

Отдаёт только идентификаторы Золотых записей и оценку совпадения — карточку
дочитывайте точным поиском или по своему идентификатору. Поиск по имени
предназначен для того, чтобы найти нужного человека, а не выгрузить базу; на
маршруте действует ограничение частоты запросов.
