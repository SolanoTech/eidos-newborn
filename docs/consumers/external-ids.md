# Внешние идентификаторы

Внешний идентификатор связывает Золотую запись с идентификатором клиента в
конкретной системе. По связке платформа узнаёт клиента при следующей передаче
данных, а системы находят Золотую запись по своему номеру клиента.

## Когда связка появляется сама

Связка создаётся автоматически, только когда источник **создаёт** новую
Золотую запись: идентификатор из поля-идентификатора его контракта
привязывается к записи.

Связка **не** создаётся, когда карточка источника сопоставилась с уже
существующей записью по реквизитам. Типичный случай: клиент пришёл сначала из
CRM, потом из банка. Запись создана CRM, данные банка в неё слились, но поиск
по номеру клиента в банке ничего не найдёт. Создайте связку явно.

## Когда привязывать вручную

- после слияния по реквизитам — чтобы источник находил запись по своему номеру;
- система-потребитель хочет хранить соответствие «свой номер клиента — Золотая
  запись» на стороне платформы;
- источник сменил идентификатор клиента.

## Правила

- Связка — это тройка «Золотая запись + источник + внешний идентификатор».
- У записи может быть не больше одной связки с каждым источником.
- Пара «источник + внешний идентификатор» уникальна: один номер в системе не
  может указывать на две записи.
- Источник указывается кодом и должен быть зарегистрирован **в ядре** — см.
  [Регистрация источника](../sources/registration.md#регистрация-в-ядре).
- В текущей версии код источника берётся из тела запроса, а не из токена.
  Указывайте код своей системы.

API работает только для физлиц.

## Привязать

```http
POST /api/v1/external/golden-records/{grClientId}/external-id
X-Access-Token: <токен>
Content-Type: application/json

{"source": "bank-1", "externalId": "CL-778812"}
```

| Ответ | Значение |
|---|---|
| `201` | Связка создана. В теле — связка с вложенными записью и источником |
| `400` `External ID for source … and client … already exists` | У записи уже есть связка с этим источником — используйте изменение |
| `404` `Source Not Found` | Источника нет в ядре |
| `404` `Golden Record … not found` | Записи нет |
| `500` | Этот номер в системе уже привязан к другой записи |

## Изменить по идентификатору записи

```http
PUT /api/v1/external/golden-records/{grClientId}/external-id
X-Access-Token: <токен>
Content-Type: application/json

{"source": "bank-1", "externalId": "CL-990001"}
```

Заменяет номер в существующей связке записи с этим источником. Если связки
нет — `404` `External ID for source … and client … does not exist`.

## Изменить по прежнему номеру

Если идентификатор Золотой записи неизвестен, а известен прежний номер в
системе:

```http
PUT /api/v1/external/golden-records/external-id
X-Access-Token: <токен>
Content-Type: application/json

{"source": "bank-1", "oldExternalId": "CL-778812", "newExternalId": "CL-990001"}
```

Если связки с прежним номером нет — `404`
`External ID CL-778812 for source bank-1 does not exist`.

!!! warning "Проверяйте результат изменения поиском"
    В текущей версии ответ на запросы изменения может завершиться ошибкой
    `500` уже после того, как изменение сохранено. Проверяйте результат
    поиском по новому номеру:
    `GET /api/v1/external/golden-records/search/source-id?source=…&source_id=…`.

## Посмотреть связки записи

Внутренний API ядра отдаёт все связки записи:

```http
GET /api/v1/internal/golden-records/{grClientId}/external-ids
```

```json
[
  {"sourceName": "bank-1", "externalId": "CL-990001", "active": true, "createdAt": "2026-10-04T11:20:01.512"},
  {"sourceName": "crm", "externalId": "CRM-000123", "active": true, "createdAt": "2026-10-04T10:15:30.481"}
]
```

В консоли связки показаны в карточке «Клиент 360» в блоке «Связанные
идентификаторы» и в карточке юрлица.
