# Регистрация источника

Источник регистрируется в двух местах: в **реестре** (`eidos-stage`) и в
**таблице источников ядра** (`eidos-core`). Почему так —
[Источники, доверие и контракты](../concepts/sources-and-contracts.md#где-хранятся-источники).

## Регистрация в реестре

### В консоли

**Источники → Новый источник**, заполните:

| Поле | Требования |
|---|---|
| Код | Уникальный, латиницей, без пробелов, например `bank-1`. После начала приёма код не меняйте: он записан в происхождение полей, статистику и связки внешних идентификаторов |
| Уровень доверия | Целое число. Консоль предлагает 1–10 |
| Название | Любое, для людей |
| Токен доступа | Нажмите **Сгенерировать** — консоль создаст токен вида `tk_…` из 24 случайных байт. Можно задать свой, он должен быть уникальным |
| Источник активен | Отображается в консоли и дашборде; на приём в текущей версии не влияет |

Подробнее об экране — [Источники и уровни доверия](../console/sources.md).

### Через API

```bash
curl -s -X POST http://<stage>:8081/internal/api/v1/sources \
  -H "X-Admin-Token: $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"code":"bank-1","name":"Банк — АБС","token":"<токен>","trustLevel":8,"enabled":true}'
```

Ответ `201` содержит карточку источника с `id`. Если код или токен уже заняты —
`400` с пояснением. Справочник — [API eidos-stage](../reference/api/stage.md#источники).

Токен генерируйте криптографически стойким генератором, например:

```bash
echo "tk_$(openssl rand -base64 24 | tr '+/' '-_' | tr -d '=')"
```

## Регистрация в ядре

Ядро принимает данные только от источников из собственной таблицы `source` и
берёт из неё уровень доверия для слияния. API для этой таблицы нет, источник
добавляется SQL-командой в базе `eidos_core`:

```sql
INSERT INTO source (source_name, trust_level)
VALUES ('bank-1', 8)
ON CONFLICT (source_name) DO UPDATE SET trust_level = EXCLUDED.trust_level;
```

На стенде из Docker Compose:

```bash
docker compose exec -T postgres psql -U postgres -d eidos_core -c \
  "INSERT INTO source (source_name, trust_level) VALUES ('bank-1', 8)
   ON CONFLICT (source_name) DO UPDATE SET trust_level = EXCLUDED.trust_level;"
```

- `source_name` должен **в точности совпадать с кодом** источника в реестре.
- `trust_level` должен совпадать с уровнем в реестре: в слиянии участвует
  значение из ядра, а консоль показывает значение из реестра.
- Команда идемпотентна: повторный запуск обновит уровень доверия.

Если пропустить этот шаг, шлюз примет данные источника, а ядро их отклонит:
источник получит `422` с текстом `eidos-core rejected record for source=<код>`,
а данные окажутся в очереди разбора с причиной «неизвестный источник».

## Смена уровня доверия

1. Измените уровень в реестре (консоль или `PUT /internal/api/v1/sources/{id}`).
2. Выполните ту же SQL-команду в ядре с новым значением.

Новый уровень действует для следующих карточек. Владельцы уже сохранённых полей
не меняются, но сравнение при следующем слиянии идёт с новым уровнем.

## Смена токена

Изменение токена в реестре действует немедленно: старый токен перестаёт
приниматься на следующем же запросе, одновременно у источника действует только
один токен. Порядок:

1. Договоритесь с интегратором о времени переключения.
2. Задайте новый токен (консоль: **Изменить → Сгенерировать**, или
   `PUT /internal/api/v1/sources/{id}` с новым `token` и прежними остальными
   полями).
3. Передайте токен по защищённому каналу; интегратор обновляет его у себя.

Карточки, отправленные со старым токеном в промежутке, получат `401` по REST
или будут пропущены при чтении из Kafka.

## Приостановка источника

Флаг «Источник активен» в текущей версии приём не останавливает. Чтобы
временно прекратить приём, смените токен и не передавайте его источнику. Чтобы
остановить только поток из Kafka, выключите потребителя соответствующего
топика — это остановит приём из топика для всех источников.

## Удаление источника

Удаление через консоль или `DELETE /internal/api/v1/sources/{id}` убирает
источник из реестра: токен перестаёт действовать. Ограничения текущей версии:

- источник, у которого есть дата-контракт, удалить не получится: API не умеет
  удалять контракт целиком, а реестр не даёт удалить источник со ссылками на
  него;
- строка источника в ядре остаётся: на неё ссылаются происхождение полей и
  внешние идентификаторы, и удалять её не нужно.

Чтобы вывести источник из эксплуатации, смените ему токен и удалите правила
контракта.
