# eidos-gateway

Внешний интерфейс платформы: единственная дверь, через которую системы-источники
передают данные и обращаются к сервисам. Проверяет, кто пришёл, соответствует ли
присланное дата-контракту, и маршрутизирует дальше.

## Что делает

**Авторизует источник** по токену в заголовке `X-Access-Token` и подставляет код
источника в сообщение сам. Источник своё имя не объявляет и подменить его не
может.

**Проверяет данные против контракта** до того, как они попадут в платформу:
обязательность полей, форматы, типы. Не прошедшее отбивается с перечнем
нарушений и попадает в статистику отказов.

**Принимает двумя способами** — синхронно по REST и потоком из Kafka. В Kafka
поднимается по одному потребителю на включённую конфигурацию, топик задаёт тип
сущности.

**Разделяет вертикали каналом.** У физлиц и юрлиц свои эндпоинты и свои топики:
тип сущности определяется каналом, а не содержимым сообщения.

**Проксирует** обращения к Золотой записи и к сервису согласий, скрывая
внутреннее устройство платформы за чистыми внешними путями.

## Установка

```bash
docker compose up -d eidos-gateway
```

Поднимет заодно PostgreSQL, Kafka и сервисы, в которые gateway маршрутизирует.
Отдельно, без приложения:

```bash
docker compose up -d postgres kafka
```

Локально из исходников (нужен JDK 26):

```bash
cd eidos-gateway && ./mvnw spring-boot:run
```

Тесты:

```bash
cd eidos-gateway && ./mvnw test
```

## Конфигурация

`src/main/resources/application.properties`; в контейнере переопределяется
переменными окружения.

| Ключ | Назначение |
|---|---|
| `server.port` | порт сервиса, по умолчанию `8090` |
| `spring.datasource.url` | собственная база: конфигурации потребителей Kafka |
| `eidos.registry.datasource.url` | реестр источников и контрактов, только на чтение |
| `gateway.admin-token` | токен административного API (заголовок `X-Admin-Token`) |
| `eidos.core.base-url` | адрес eidos-core |
| `eidos.stage.base-url` | адрес eidos-stage |
| `eidos.consents.base-url` | адрес сервиса согласий |

Адрес брокера, топик и группа для каждого потребителя хранятся не в конфигурации,
а в базе gateway и меняются через административный API без перезапуска.

## Эндпоинты

### Внешние — для систем-источников

Требуют заголовок `X-Access-Token` с токеном источника.

| Метод | Путь | Назначение |
|---|---|---|
| `POST` | `/api/v1/client-data` | карточка физлица, тело `{"data": {...}}` |
| `POST` | `/api/v1/legal-data` | карточка юрлица, тело то же |
| `POST` | `/api/v1/consents` | зарегистрировать согласие клиента |
| `GET` | `/api/v1/consents/client/{clientId}` | согласия клиента по всем типам |
| `GET` | `/api/v1/consents/active/{clientId}` | действующее согласие одного типа, параметр `type` |
| `GET` | `/api/v1/external/golden-records/**` | поиск и внешние идентификаторы, прозрачно в eidos-core |
| `GET` | `/health` | проба живости |

Ответы приёма: `200` при успехе, `401` без токена или с неизвестным токеном,
`422` при нарушении контракта с перечнем нарушений в теле.

Идентификатор клиента в согласиях принимается в обеих формах — с префиксом
`GR_` и без него. Код источника в теле передавать не нужно: он всё равно будет
заменён на код из токена.

### Внутренние — администрирование

Закрыты заголовком `X-Admin-Token`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/internal/api/v1/kafka-config` | действующие конфигурации потребителей |
| `GET` | `/internal/api/v1/kafka-config/all` | все конфигурации, включая выключенные |
| `PUT` | `/internal/api/v1/kafka-config` | изменить конфигурацию; потребители перезапускаются на лету |
